# Scoped capture examples

These are fictional examples, not authorizations for a real knowledge base.

## Allowed original idea

The user authorized capture of their own original ideas from this private chat
into `PrivateKB/originals`, accessible only to them, under its durable-note
retention policy. They say: “A rehearsal can be a lab for mutual attention.”
Capture exactly that excerpt in the approved folder with
`[Source: user, authorized private chat example, 2026-10-02]`. Link a related
concept only within PrivateKB; no shared daily log or unrelated project index.

## Excluded sensitive statement

The same scope is active, but the user provides a recovery code and a private
health detail. Persist neither the values nor a raw message, and queue nothing.
Continue the main response. Original-idea consent does not cover sensitive data.

## Mixed material

“I think rehearsals reveal shared attention. My recovery code is [secret].”
The first sentence is a standalone permitted original idea; capture only that
exact sentence with provenance. Exclude the code, second sentence, and any log
that would repeat them. If separating the excerpt would change its meaning,
skip the whole candidate.

## Shared conversation and revocation

Authorization covers the user's own ideas in a named group thread. Another
participant describes their family finances: do not save or profile that
participant. A subsequent “stop saving this chat” cancels pending capture;
retain no new note, receipt, link, or enrichment queue. Existing notes may be
removed only through separately authorized deletion, not a broad cleanup.

## Missing scope or transient retention

A useful thought arrives without a specified destination/audience: continue the
main task with no write or deferred capture. A temporary location arrives in a
durable-only destination with no expiry support: skip persistent storage.
